Chaining Actions

Add a third action. Watch the planner sequence all three automatically.

What We Add

assessRisk — needs two inputs from the Blackboard

@Action fun assessRisk( application: LoanApplication, // needs this AND score: CreditScore, // needs this ai: Ai, ): RiskAssessment = // produces this ai.withDefaultLlm() create """ Assess the risk of this loan. Applicant: ${application.applicantName} Amount: ₹${application.amount} Credit score: ${score.score} (${score.rating}) Return: approved, riskLevel (Low/Medium/High), reason. """.trimIndent()
This action needs both LoanApplication and CreditScore on the Blackboard. The planner must run extractApplication and evaluateCredit first. You wrote zero ordering code.
The GOAP Planner

It works backwards from the goal

1
Planner asks: what do I need to run assessRisk? → LoanApplication + CreditScore
2
CreditScore not on Blackboard → which action produces it? → evaluateCredit
3
evaluateCredit needs LoanApplication → not on Blackboard → which action produces it? → extractApplication
4
extractApplication needs UserInput → that's the starting input. Plan found.
Final plan: extractApplication → evaluateCredit → assessRisk. Computed automatically. Replanned after every step.
The Power

Add an action. It gets incorporated automatically.

You added assessRisk and didn't touch a single line of existing code. No pipeline config. No state machine update. No import changes. The planner found its place on its own.

Traditional pipeline
Add step → edit the pipeline definition → update all state transitions → test everything breaks
Embabel GOAP
Add @Action method → done. Planner incorporates it automatically on next run.
This is why the project description says "Superior extensibility and reuse." You extend the system without editing existing code.
